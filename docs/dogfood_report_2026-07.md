# 狗粮报告：第一次真实使用（2026-07-26）

方法：全程通过 MCP 工具面（真实客户端路径），喂入本项目开发史的
29 条真实知识（事实/偏好/事件/琐事），运行 19 个真实查询
（17 正例 + 2 界外负例），实战生命周期（取代/睡眠/解释/反馈）。
评测脚本在 `dogfood_data/`（feed.py / query.py）。

## 结论

正例检索质量良好（top3 召回 17/17 稳定，top1 ~13/17），
睡眠巩固与解释工具按设计工作；但狗粮第一天就咬出 3 个探针
永远测不出的真实缺陷，全部已修复并有回归测试。

## 发现与处置

### 🔴 已修复

1. **弃答完全失效（0/2）**。库里根本没有的主题（"明年的融资计划"），
   系统自信地返回记忆——中文 bigram 总能碎片匹配到点什么，而
   `_review` 置信度与查询相关性无关。
   修复：查询词汇的索引覆盖率信号 + 分级软标注（<45% 强警告 +
   置信度减半 + QUESTIONABLE；<60% 谨慎提示）。
   **重要教训**：曾按"负例 0.38 vs 最低正例 0.54"设硬弃答阈值，
   随即被真实改述查询推翻——"中英文词汇割裂问题"（正例）覆盖率
   仅 0.29，比负例还低。无嵌入的词面覆盖不可做硬弃答，只能
   诚实标注并把判断权交给调用方。

2. **取代链的数字盲区**。"版本是 0.1.0"→"版本是 0.2.0" 整体
   Jaccard ≥0.8 被判 NOOP（近重复强化），旧版本号继续冒充现状。
   知识更新探针用城市名（里斯本→柏林）词面差异大，测不出这类
   **数字微差**——而真实世界的事实更新恰恰多是版本/价格/日期微差。
   修复：值 token（数字串）检测优先于近重复判定，数字变化必走
   SUPERSEDE（新规则 R3b_value_only_change）；UPDATE 同样排除
   值变化场景。

3. **访问计数通胀**。一轮评测（19 查询）就把 29 条记忆的访问
   计数刷到 40+，ACT-R 频率效应让"热门"记忆霸榜，共激活边疯长
   ——第二轮评测的结果因此漂移（观测即使用）。
   修复：访问与共激活各加 60 秒去抖窗口（窗口内重复命中是
   同一次"使用"）。修复后两轮评测计数稳定为 1，结果不再漂移。

4. **MCP 存的事实全按最快衰减处理**。`memory_add` 无类型参数，
   一切走 INTERACTION（衰减最快、不参与取代管理）。
   修复：新增 `memory_type` 参数（fact/preference/story/idea），
   非 interaction 类型走锚点抽取 + `add_memory` 决策表路径。

### 🟡 已记录，未修（下轮候选）

5. **单次检索返回 15 条**：core_limit(10) + 联想追加 + both 路径
   合并叠加，对客户端是噪声轰炸。候选方案：最终结果截断 + 按
   综合分排序后取 top-N。
6. **MCP 无程序记忆工具**：add_procedure/工作流类知识没有入口。
7. **观察**：评测即使用是记忆系统的本性，评测框架应默认在
   store 副本上运行（tot_lite 已用独立目录，狗粮脚本已重建库）。
